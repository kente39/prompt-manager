# 나만의 책 관리 프로그램

읽었거나 읽고 싶은 책을 콘솔에서 추가·조회·검색·보유관리할 수 있는 Python 프로그램입니다.
Python 표준 기능만 사용하며, 별도 설치 없이 바로 실행됩니다.

- **GitHub 저장소:** https://github.com/kente39/prompt-manager
- 공개(Public) 저장소이며, 위 주소에서 코드·커밋 이력·README를 확인할 수 있습니다.

## 실행 방법

```bash
git clone https://github.com/kente39/prompt-manager.git
cd prompt-manager
python app.py
```

이미 코드가 있으면 `python app.py`만 실행하면 됩니다. Python 3.10 이상이 필요하며, 실행 시 버전을 자동으로 확인합니다.

```
=== 나의 책 관리 ===
1. 책 추가
2. 책 목록
3. 장르별 조회
4. 검색
5. 상세 보기
6. 보유 상태 관리
7. 보유 목록
0. 종료
선택:
```

## 기능

| 번호 | 기능 | 설명 |
| --- | --- | --- |
| 1 | 책 추가 | 제목·저자·장르를 입력해 새 책 등록 |
| 2 | 책 목록 | 전체 책을 번호·장르·저자·보유 여부와 함께 출력 |
| 3 | 장르별 조회 | 선택한 장르에 속한 책만 출력 |
| 4 | 검색 | 제목·저자에 검색어가 포함된 책 찾기(대소문자 무시) |
| 5 | 상세 보기 | 번호로 고른 책 1개의 제목·저자·장르·보유 여부 출력 |
| 6 | 보유 상태 관리 | 번호로 고른 책의 보유/미보유를 켜고/끄기(토글) |
| 7 | 보유 목록 | 보유(📖) 중인 책만 모아서 출력 |
| 0 | 종료 | 프로그램 종료 |

### 기능별 입출력 예시

- **추가:** `제목: 사피엔스` → `저자: 유발 하라리` → `장르: 2` 입력 시 목록에 새 책 추가
- **검색:** `검색어: 위어` → 제목·저자에 "위어"가 든 책 출력(대소문자 구분 없음)
- **상세 보기:** `상세 볼 번호: 1` → 1번 책의 제목·저자·장르·보유 여부 출력

## 데이터 구조

책 데이터는 **리스트 안에 딕셔너리**가 들어간 형태입니다.

```python
books = [
    {"title": "어린 왕자", "author": "생텍쥐페리", "genre": "소설", "owned": True},
    {"title": "프로젝트 헤일메리", "author": "앤디 위어", "genre": "SF", "owned": False},
    ...
]
```

- 바깥 **리스트**(`[]`)는 책 여러 권을 순서대로 담습니다.
- 안쪽 **딕셔너리**(`{}`)는 책 한 권의 정보를 키로 묶습니다: `title`(제목), `author`(저자), `genre`(장르), `owned`(보유 여부, `True`/`False`).
- 특정 값 접근은 **리스트 번호 + 딕셔너리 키**로 합니다. 예: 세 번째 책의 제목은 `books[2]["title"]`.

### 왜 리스트 + 딕셔너리인가 (자료구조 선택 이유)

| 구분 | 리스트 `[]` | 딕셔너리 `{}` |
| --- | --- | --- |
| 담는 것 | 여러 개를 순서대로 | 한 대상의 여러 속성을 이름표로 |
| 꺼내는 법 | 번호(인덱스) `books[0]` | 이름(키) `b["title"]` |
| 장점 | 순서대로 반복·정렬이 쉬움 | 이름으로 찾아 의미가 분명 |
| 단점 | 몇 번째가 무엇인지 외워야 함 | 여러 개를 순서대로 다루긴 불편 |

책은 **여러 권**을 다뤄야 하므로 전체는 리스트로, 책 **한 권**은 제목·저자·장르·보유여부라는 **여러 속성**을 가지므로 딕셔너리로 표현했습니다. 만약 책 하나를 `["어린 왕자", "생텍쥐페리", "소설", True]`처럼 리스트로만 만들면 `b[2]`가 장르라는 걸 순서로 외워야 하고, 중간에 항목을 추가하면 번호가 밀려 코드가 깨집니다. 딕셔너리는 `b["genre"]`라 순서가 바뀌어도 안전합니다.

## 메뉴 루프 설계

`main()`은 `while True`로 메뉴를 **반복** 출력합니다. 사용자가 기능을 하나 처리하면 다시 메뉴로 돌아오도록 하기 위해서입니다.

- **종료 조건:** 사용자가 `0`을 입력하면 종료 메시지를 출력하고 `break`로 반복을 빠져나옵니다. 이 조건이 없으면 프로그램이 끝나지 않습니다.
- 그 외 번호는 해당 기능 함수를 호출하고, 정의되지 않은 입력은 허용 범위를 안내한 뒤 다시 메뉴로 돌아옵니다.

## 입력 처리

잘못된 입력에 프로그램이 멈추지 않도록 검증을 넣었습니다.

- 빈 값을 입력하면 다시 입력을 요청합니다(`input_non_empty`).
- 숫자가 아니거나 범위를 벗어난 번호는 거르고 다시 요청합니다(`input_number`).
- 메뉴에서 잘못된 번호를 입력하면 허용 범위(0~7)를 함께 안내합니다.

## 장르 수정 방법

장르 목록은 `app.py` 상단의 `genres` 변수에 정의돼 있습니다.

```python
genres = ["소설", "에세이", "자기계발", "SF", "만화", "미스터리"]
```

이 리스트의 항목을 추가·삭제·변경하면 메뉴의 장르 선택지에 그대로 반영됩니다. 책 추가 시에는 이 목록에서 번호로 고르거나, `0`을 눌러 목록에 없는 장르를 직접 입력할 수 있습니다.

## 검색 동작과 한계

검색은 입력한 키워드가 **제목 또는 저자**에 포함되어 있는지를 확인하며, `.lower()`로 **대소문자를 구분하지 않습니다**. 부분 문자열 일치 방식이라, 정확한 제목을 몰라도 일부만 입력하면 찾을 수 있습니다. 다만 띄어쓰기·오타까지 보정하지는 않으므로, 필요하면 공백 제거나 유사어 검색으로 확장할 수 있습니다.

## 중복 제목 처리 정책

현재 버전은 **동일한 제목의 책도 추가를 허용**하며, 목록에서는 번호로 구분합니다. 같은 제목이 여러 권 있어도 상세 보기·보유 관리는 번호로 정확히 지정되므로 동작에 문제가 없습니다. (엄격한 중복 금지가 필요하면 추가 시 기존 제목과 대조해 거부하는 검사를 넣어 확장할 수 있습니다.)

## 데이터 저장 방식

책 정보는 **프로그램 실행 중에만 메모리에 저장**되며, 종료하면 초기화됩니다. 기본 책 3권이 미리 등록되어 있어 실행 직후 바로 기능을 확인할 수 있습니다.

파일 영속화(예: JSON 저장)는 이 과제의 **보너스**입니다. JSON으로 저장하면 종료 후에도 데이터가 유지되는 장점이 있지만, 파일 입출력·예외 처리가 추가로 필요합니다. 이번 필수 버전은 메모리 전용으로 단순하게 구현했습니다.

## 코드 구조

기능별로 함수를 분리했으며, `main()`에서 메뉴 루프를 돌며 선택에 따라 각 함수를 실행합니다.

- `show_menu` : 메뉴 출력
- `add_prompt` : 책 추가 · `show_list` : 목록 · `show_by_category` : 장르별 조회 · `search_prompt` : 검색 · `show_detail` : 상세 보기 · `toggle_favorite` : 보유 상태 토글 · `show_favorites` : 보유 목록
- `input_non_empty` / `input_number` : 입력 검증 유틸
- `main` + `if __name__ == "__main__":` : 실행 진입점

> 참고: 이 프로그램은 학습가이드의 프롬프트 관리 예제를 **도서 관리 소재로 옮긴 버전**입니다. 함수 이름은 원본 구조를 그대로 따르되(`add_prompt`, `toggle_favorite` 등), 다루는 데이터만 책으로 바꿨습니다. 데이터 필드는 원본의 `content·category·favorite`를 각각 `author·genre·owned`(저자·장르·보유여부)로 대응시켰습니다.

## Git 작업 방식

- **커밋 정책:** 기능 하나 = 커밋 하나 원칙으로 나눠, 의미 있는 커밋을 10개 이상 유지합니다.
- **브랜치 정책:** 새 기능(예: 실행 시 Python 버전 확인)은 `feature/…` 브랜치에서 개발한 뒤 `main`에 병합했습니다. `main`을 항상 동작하는 상태로 유지하기 위함입니다.
- **병합 충돌이 나면:** 충돌 파일을 열어 `<<<<<<<`·`=======`·`>>>>>>>` 표시 사이에서 남길 코드를 고른 뒤 표시를 지우고, `python app.py`로 정상 동작을 확인한 다음 `git add` → `git commit`으로 마무리합니다.
